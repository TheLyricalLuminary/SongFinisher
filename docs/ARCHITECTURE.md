# Song Finisher — Architecture Specification

> Approved 2026-07-09. This document is the implementation contract for the MVP.
> Mission: *Play a melody. Get lyrics that fit.* A melody-to-lyric copilot — not a chatbot,
> not a generic lyric generator.

## 1. Executive summary & key decisions

A native iOS app (Swift 6 + SwiftUI only, iOS 17+, MVVM, unit test target) built as one
long-running pipeline:

```
AVAudioEngine tap → lock-free ring buffer → AnalysisWorker thread
  (YIN pitch / onset / tempo / phrase segmentation)
  → PhraseSpec (syllable budget + stress map + emotion)
  → LyricProviding (Foundation Models, offline fallback)
  → deterministic re-scoring + ranking → ViewModel → UI
```

Every arrow is an `AsyncStream` of a `Sendable` value type.

1. **Local SPM packages enforce the architecture.** Domain physically cannot import SwiftUI
   because its manifest declares no such dependency — the compiler, not a lint rule, keeps
   layers honest.
2. **Service protocols live in Domain**: Features and test fakes import Domain alone.
3. **Real-time DSP on a dedicated thread, not the cooperative pool**: the mic tap does a
   memcpy only; a dedicated `Thread` runs the 10 ms hop loop, immune to pool starvation.
4. **YIN pitch detection** — its aperiodicity measure is reused three ways: UI confidence,
   voicing gate, and prompt `pitchConfidence`.
5. **Provider-agnostic AI behind `LyricProviding`.** The shipped premium path is the
   **on-device Foundation Models framework** (`FoundationModelsLyricProvider`:
   `LanguageModelSession` + `@Generable` guided output, selected at composition time when
   `SystemLanguageModel` is available, per-request fallback to the offline assembler on any
   generation failure) — nothing leaves the device. The deterministic offline provider is
   the universal fallback on non-Apple-Intelligence hardware. There is no remote provider
   and no networking code anywhere in the app: "audio never leaves the device" is
   enforced by what exists, not by policy. The seam's third-tier future is a *bundled*
   quantized open-weights model for non-Apple-Intelligence hardware — still on-device,
   added as one new `LyricProviding` conformance.
6. **The model is never the judge of objective constraints**: syllables and stress are
   recounted on-device against a bundled CMU-dict subset; objective axes carry 70% of the
   ranking weight.
7. **SwiftData, quarantined** behind a `@ModelActor` store; `@Model` classes never leave the
   persistence package.
8. **Honest degradation everywhere**: low pitch/tempo confidence widens the syllable
   tolerance and tells the model "8–10 syllables" instead of asserting a false-precise 9.

## 3. Module boundaries

Dependencies point strictly downward; SPM manifests are the rules.

```
App target (composition root)      — imports everything; only place concrete types are named
   ▼
Features (Views + ViewModels)      — imports Domain, SwiftUI. Talks to protocols only.
   ▼
MelodyKit │ LyricEngine │ PersistenceKit   — peers; NEVER import each other
   ▼
Domain                             — imports Foundation only; all protocols + models + pure logic
```

- Persistence types (`SDSong`, `SDLyricLine`) are `internal` to their package; only Domain
  types cross boundaries.
- MelodyKit doesn't know lyrics exist; LyricEngine doesn't know microphones exist. The
  `PhraseSpec` connects them, and the connecting code lives in `SessionViewModel`.
- Swift 6 language mode (full data-race safety) in every target from the first commit.

## 4. Data models (Domain — all `Sendable, Equatable, Codable` value types)

```swift
struct PitchFrame { let time: TimeInterval; let frequencyHz: Double?; let midiNote: Double?
                    let rmsEnergy: Float; let confidence: Float }        // YIN clarity 0…1

struct NoteEvent  { let onset, duration: TimeInterval; let midiNote: Double
                    let peakEnergy: Float; let beatStrength: Float; let isMelisma: Bool }

struct TempoEstimate { let bpm: Double; let confidence: Float; let beatPhase: TimeInterval }

struct Phrase { let id: UUID; let index: Int; let start, end: TimeInterval
                let notes: [NoteEvent]; let endsWithCadence: Bool
                let pitchConfidence: Double }

enum Stress: String { case strong = "S", weak = "w" }
struct StressMap  { let pattern: [Stress]; let noteToSyllable: [Int] }   // melisma merge map
struct SyllableBudget { let target: Int; let tolerance: Int; let stressMap: StressMap }
                    // tolerance widens automatically under low confidence

enum Emotion: String, CaseIterable { case longing, joy, nostalgia, reflection,
                                          tension, release, hope, melancholy }
struct EmotionScore { let emotion: Emotion; let confidence: Float }      // sums to 1 across set

enum ContourShape: String { case rising, falling, arch, valley, flat }

struct PhraseSpec {                       // the single value handed to the AI layer;
    let phraseID: UUID                    // ALSO the fixture-golden format for DSP tests
    let budget: SyllableBudget
    let emotions: [EmotionScore]          // top-3 sent to model
    let tempoBPM: Double; let tempoConfidence: Float
    let contourShape: ContourShape
    let noteDurationsMs: [Int]            // lets the model place open vowels
    let longNoteSlots: [Int]
    let phraseDuration: TimeInterval
    let requestedEmotionOverride: Emotion?   // [Different Emotion]
    let variationSeedText: String?           // [More Like This]
}

enum ProviderKind: String { case appleIntelligence, offline }   // both on-device
struct LyricCandidate { let id: UUID; let phraseID: UUID; let text: String
    let syllableCount: Int                // recomputed on-device — never trusted
    let stressAlignment: [Stress]         // dict-derived
    let provider: ProviderKind
    let repaired: Bool                    // auto-repair (contraction/article) applied
    let modelScores: ModelScores? }       // LLM self-report, subjective axes only
struct ModelScores { let emotionalFit: Double; let memorability: Double }  // clamped 0…1

struct LyricScore {
    let syllableFit, stressFit, singability, emotionalFit, continuity, memorability: Double
    var total: Double { 0.30*syllableFit + 0.25*stressFit + 0.15*singability
                      + 0.15*emotionalFit + 0.10*continuity + 0.05*memorability }
}
struct RankedCandidate { let candidate: LyricCandidate; let score: LyricScore }

struct LyricLine { let id: UUID; let phraseID: UUID; let text: String
                   let stressMap: StressMap; let emotion: Emotion
                   let acceptedAt: Date; var isHookCandidate: Bool }
struct RejectedLine { let text: String
                      enum Reason: String { case regenerated, differentEmotion, explicitReject }
                      let reason: Reason }                      // teaches taste, not just avoidance

struct SessionMemory { var acceptedLines: [LyricLine]           // capped 12 in prompt
                       var rejected: [RejectedLine]             // capped 20, FIFO
                       var themes: [String]                     // capped 8
                       var motifs: [String]; var hookLine: String?
                       var dominantEmotion: Emotion?
                       var rhymeTails: [String] }               // "rhyme only if natural"

struct Song { let id: UUID; var title: String; var createdAt, updatedAt: Date
              var lines: [LyricLine]; var memory: SessionMemory
              var tempoBPM: Double?; var sourceMemoURL: URL? }

struct VoiceMemoAnalysis { let duration: TimeInterval; let tempo: TempoEstimate
    let phrases: [Phrase]; let specs: [PhraseSpec]
    let sections: [MemoSection]            // DTW contour clustering → "A", "B", "A′"
    let repeatedPhraseGroups: [[UUID]]     // hook candidates = most-repeated high-energy
    let dominantEmotions: [EmotionScore] }
struct MemoSection { let label: String; let phraseIDs: [UUID] }

enum SessionError: Error { case micPermissionDenied, audioEngineFailed(String),
    noPitchDetected, tooNoisy, aiUnavailable(AIUnavailableReason), persistenceFailed }
enum AIUnavailableReason { case offline, invalidKey, serverError,
                                rateLimited(retryAfterSeconds: Int?) }
```

## 5. Service interfaces (all in `Domain/Services`, Domain types only)

```swift
protocol AudioCapturing: Sendable {
    var state: AsyncStream<CaptureState> { get }        // idle/listening/paused/failed
    func start() async throws(CaptureError) -> AsyncStream<AudioChunk>  // 16 kHz mono, 64 ms
    func stop() async
}

protocol MelodyAnalyzing: Sendable {                    // pure stream transformer:
    func analyze(_ chunks: AsyncStream<AudioChunk>) -> AsyncStream<AnalysisEvent>
    func analyzeFile(at url: URL, progress: @Sendable (Double) -> Void)
        async throws -> VoiceMemoAnalysis               // memo path, ~15–20× real time
}
enum AnalysisEvent: Sendable {                          // mic, memo file, and test fixture
    case pitch(PitchFrame)                              //   are literally the same code path
    case tempoUpdated(TempoEstimate)
    case phraseInProgress(start: TimeInterval, provisionalNotes: Int)  // live syllable meter
    case phraseCompleted(Phrase)
}

protocol ProsodyDeriving: Sendable {
    func syllableBudget(for phrase: Phrase, tempo: TempoEstimate?) -> SyllableBudget
    func emotions(for phrase: Phrase, tempo: TempoEstimate?) -> [EmotionScore]
    func spec(for phrase: Phrase, tempo: TempoEstimate?, memoryHints: SessionMemory) -> PhraseSpec
}

protocol LyricProviding: Sendable {                     // THE provider-agnostic seam
    var kind: ProviderKind { get }
    func prewarm() async                                // default no-op; see §9
    func candidates(for spec: PhraseSpec, memory: SessionMemory)
        async throws(LyricProviderError) -> [LyricCandidate]
}
// Two cases, because both tiers are local. `network`, `rateLimited` and `unauthorized`
// existed for the cloud provider that was never built, and went with it.
enum LyricProviderError: Error { case invalidResponse(String), cancelled }

protocol CandidateRanking: Sendable {
    func rank(_ c: [LyricCandidate], spec: PhraseSpec, memory: SessionMemory) -> [RankedCandidate]
}

protocol SongStoring: Sendable {
    func createSong(title: String) async throws -> Song
    func fetchSongs() async throws -> [Song]
    func append(line: LyricLine, to songID: UUID) async throws
    func updateMemory(_ m: SessionMemory, songID: UUID) async throws
    func recordRejection(_ r: RejectedLine, songID: UUID) async throws
    func delete(songID: UUID) async throws
}

protocol PermissionChecking: Sendable {
    func currentMicPermission() async -> MicPermission   // undetermined/granted/denied
    func requestMicPermission() async -> MicPermission
}
```

Composition root: `AppServices` struct of protocol existentials, built once in
`SongFinisherApp`, with a first-class `.fakes()` factory for tests and previews.

service packages. `SessionViewModel` state machine:
`idle → listening → analyzingPhrase → suggesting → (accept | regenerate | …) → listening`,
with **latest-phrase-wins** supersession (in-flight generation cancelled, plus a `phraseID`
mismatch guard). Long-lived tasks cancelled by explicit `cancelTasks()` on disappear
(deinit-based cancellation is unreliable for `@Observable` VMs) — covered by a leak-check test.

## 7. Persistence strategy

**SwiftData, quarantined.** `@Model` classes (`SDSong`, `SDLyricLine`) exist only inside
PersistenceKit; a `@ModelActor SongStore` is the single writer, mapping to/from Domain structs
at the boundary. Chosen over Core Data (same store, more ceremony), GRDB (best value-type fit
but a third-party dep for a few hundred rows), and JSON files (partial-write risk).

- `SessionMemory` is a JSON `Data` blob (schema-versioned) — read/written whole, high churn as
  prompts evolve, so blob = zero migrations. Lines are real entities.
- `VersionedSchema` + empty `MigrationPlan` registered from day one.
- Raw live audio is **never persisted** (privacy). Memo audio → `Application Support/Memos/`;
  memo analyses cached as Codable JSON keyed by file SHA-256 so re-imports are instant.
- No credentials are stored, because there is no service to authenticate against: every
  generation tier runs on the device.

## 8. Audio pipeline

**Capture:** `AVAudioSession` `.playAndRecord` + `.measurement` mode (kills AGC/EQ that smears
pitch), preferred IO buffer 5 ms. `AVAudioEngine` input tap at hardware rate, buffer 1024
frames (~21 ms @ 48 kHz). **The tap does a memcpy only** into a preallocated lock-free SPSC
ring buffer (8 s capacity; the codebase's only `@unchecked Sendable`, with documented
invariant + stress test). No allocation, no locks, no Swift concurrency on that thread.

**AnalysisWorker:** a dedicated `Thread` (`.userInteractive` — not GCD, not the cooperative
pool, immune to starvation) drains the ring, high-passes at 60 Hz and decimates once to
**16 kHz mono** (vDSP polyphase FIR), then runs a **10 ms hop loop (160 samples)**; all FFT
setups and scratch buffers preallocated (a DEBUG malloc-hook test asserts zero allocations
after warm-up).

- **Pitch — YIN** (CMNDF, FFT-accelerated): window 1024 (64 ms), threshold 0.15, range
  65–1047 Hz, parabolic interpolation (cents-level), 5-frame median filter (2-frame causal
  delay), voicing hysteresis (enter > 0.88, exit < 0.80 confidence, plus RMS ≥ rolling noise
  floor + 6 dB). ~0.15 ms/frame on A15. Chosen over MPM (near-tie; YIN's aperiodicity gives a
  calibrated confidence for free), FFT-peak/HPS (bin quantization, octave errors), CREPE/pYIN
  (model dep, +latency).
- **Onsets:** half-wave-rectified log-magnitude spectral flux (1024-pt FFT, 100 Hz–5 kHz),
  adaptive median+MAD threshold, 50 ms dead time — **fused with pitch-jump onsets** (> 60
  cents sustained 3 frames) for legato singing that energy flux misses.
- **Notes:** open on onset, close on next onset / unvoicing ≥ 60 ms; < 60 ms notes merged
  forward; glides without re-articulation flagged `isMelisma` (consume one syllable slot via
  `noteToSyllable`).
- **Tempo:** autocorrelation of the onset-strength envelope, 8 s sliding window every 2 s,
  60–200 BPM with log-Gaussian prior at 105 BPM, harmonic disambiguation, smoothing
  hysteresis; below confidence 0.35 the stress mapper drops the beat grid and the HUD shows "~".
- **Phrase segmentation:** boundary on (a) silence ≥ 350 ms (workhorse); (b) cadential long
  note (≥ 1.5× median duration) + 150 ms quiet — fires ~200 ms earlier; (c) 12 s hard cap.
  Minimum phrase: 2 notes and 700 ms. A *tentative-end* event at 200 ms feeds the UI (and is
  the post-MVP hook for speculative pre-warm). `phraseInProgress` events make the syllable
  meter fill live so users see "it heard 6, I sang 7" and re-hum.
- **Stress map:** one slot per non-melisma note (clamped 1–16); prominence = weighted vote of
  metric accent (beat-grid alignment, only if tempo confidence ≥ 0.35) + agogic (duration) +
  dynamic (RMS) + pitch-peak accents; ≥ threshold → `S`, at least one `S` guaranteed. Low
  confidence ⇒ `tolerance` widens instead of asserting a wrong map.
- **Emotion:** ~10-feature vector (tempo, Krumhansl–Schmuckler mode-ness, contour slope,
  range, mean interval, note density, mean duration, articulation ratio, energy arc,
  ends-on-descent) → transparent 8-label weight matrix (in a plist, tunable without code) →
  softmax. Top-3 distribution goes to the model, never a single hard label.
- **Hybrid melodic/rhythmic routing (guitar chords):** YIN is monophonic by design, so a
  `PolyphonyDetector` watches every energetic hop — a frame is polyphonic when ≥ 2 strong
  spectral peaks are inharmonic against YIN's own f0 (a chord's fifth/third), or when YIN
  collapses under a strong, spectrally dense signal (the strum attack). Ratio math alone
  can't do it: a missing-fundamental note and a root+fifth chord are spectrally the same
  family; time-domain periodicity is the tiebreaker. Votes smooth over ~0.5 s (enter
  rhythmic ≥ 50%, exit ≤ 15%; silence never votes). In **rhythmic mode** the pitch path is
  bypassed and a `RhythmSegmenter` builds `isRhythmOnly` phrases from the onset pocket
  (a "note" = one strum's ring-out, placeholder pitch). Their specs come from rhythm alone:
  syllable budget = onset grid × user-selected `SyllableDensity` (sparse 1× / medium 1.5× /
  dense 2× per strum), stress from beat-grid + agogic + dynamic prominence, long-note slots
  from long ring-outs, contour `flat`, pitch-derived emotion features neutral, tolerance
  never below ±1 (the budget is an estimate by construction). Tempo keeps tracking the flux
  envelope in both modes; mode flips flush the outgoing segmenter first, then emit
  `inputModeChanged`. Top-note melody extraction for arpeggiated lines is a deferred
  enhancement; full polyphonic transcription is out of scope.

**Honest latency budget** (includes window group delay and median-filter delay):

| Stage | Cost |
|---|---|
| Mic + IO buffer + tap delivery | ~25 ms |
| Hop wait + YIN window group delay (window/2) | ~42 ms |
| Median filter (causal) | 20 ms |
| Thread→MainActor hop + 30 fps coalesce | ≤ 33 ms |
| **Live pitch/waveform feedback** | **≈ 90–120 ms** |
| Phrase-end confirmation (silence gate) | +350 ms after last note |
| Budget/stress/emotion (pure math) | < 10 ms |
| **Offline placeholder suggestion on screen** | **≈ 400 ms after phrase ends** |
| Foundation Models generation (on-device, warmed) | sub-second typical; **first call pays model load unless prewarmed** |

## 9. AI integration layer

**Every tier runs on the device. There is no remote provider, no API key, and no
networking code anywhere in the app** — the privacy claim is a property of what exists,
not a policy promise. What follows describes the shipped design; an earlier revision of
this document specified an Anthropic-backed cloud tier that was **never built** and whose
scaffolding has since been deleted.

**Composition** (`AppServices.bestAvailableLyricProvider`, chosen once at launch):

| Tier | When | Badge |
|---|---|---|
| `FoundationModelsLyricProvider` | `SystemLanguageModel` available — Apple Intelligence hardware | ON-DEVICE AI |
| `OfflineLyricProvider` | everywhere else, and once a free user's daily premium budget is spent | OFFLINE DRAFT |

The premium provider holds the offline one as its `fallback` and degrades **per request**:
a guardrail refusal, context overflow, or empty batch returns offline candidates rather
than an error banner, because a musician mid-flow should never be interrupted by a
generation that balked at one phrase. `CancellationError` never triggers fallback.

Because the tier is chosen at composition time but the premium path can fall back
internally, `services.lyrics.kind` reports what was *composed* and `candidate.provider`
reports what actually *ran*. Only the latter is trustworthy after the fact, and it is what
badges the card.

**A third tier is anticipated but not built**: a bundled quantized open-weights model for
hardware without Apple Intelligence, so every device gets real generation. It is one new
`LyricProviding` conformance — still on-device. The binding constraint is peak resident
memory on a 4 GB A15, which is unmeasured.

**Cold start:** Foundation Models lazy-loads on first request, which surfaced in real
sessions as seconds of suggestion spinner on the very first phrase. `LyricProviding.prewarm()`
(default no-op; overridden by the Foundation Models tier) is fired when a listening session
starts, so the load happens while the writer is still settling in front of the mic.

**Structured output:** `LanguageModelSession` + `@Generable` guided generation constrains
decoding to `GeneratedLyricBatch`, so there is no JSON parsing and no malformed-response
path. Sessions are per-request and stateless — all cross-phrase continuity travels in the
prompt via `SessionMemory`.

**Response handling:** guided generation hands back a decoded `GeneratedLyricBatch`, so
there is no wire format to inspect — no `stop_reason`, no partial-JSON salvage, no refusal
envelope. (Earlier revisions of this section described all three; they belonged to the cloud
tier that was never built.) Clamp the self-reported scores, then **recount every candidate's
syllables on-device**: exact within tolerance → keep; ±1 → auto-repair (contract "I am"→"I'm",
drop/add an article, flagged `repaired`); ±2+ → drop. Fewer than 3 survivors → one silent
corrective retry quoting the failures back ("these had 8 syllables, not 7: …"), then blend
offline candidates.

**Intent semantics:** `[Use]` = no API call (append line, update rhymeTails/themes/motifs +
harvest `theme_observation`, persist). `[More Like This]` = variation-of-exemplar intent.
`[Regenerate]` = shown candidates recorded as `RejectedLine(.regenerated)`, avoid-list grows.
`[Different Emotion]` = emotion block replaced with override.

**Ranking (deterministic 70% / LLM 30%):** on-device — `syllableFit` (CMU-dict recount,
−0.35/syllable off), `stressFit` (lexical stress of content words vs `S` slots; function words
float), `singability` (open vowels on long notes, consonant-cluster penalties), `continuity`
(rhyme-tail match +, motif echo +, near-verbatim copy −). From LLM, clamped — `emotionalFit`,
`memorability`. Weights in a plist. `syllableFit < 0.3` is a hard drop.

**Offline provider:** a template bank filled by **beam search over a 35,346-word lexicon**
(`Resources/lexicon.bin`, SFLX v1 — CMUdict pronunciations + Moby POS + wordfreq Zipf +
VADER valence, built by `tools/build_lexicon.py`). Templates are POS frames; the beam lays
words down left-to-right scoring stress-on-strong-beat, open-vowel-on-long-note and
consonant-cluster-on-fast-note, so **outputs satisfy the stress map by construction**.
Seeded RNG (`phraseID ^ attempt`) so Regenerate varies deterministically and tests are
exact-match.

It has exactly one error path, and it is the one that cannot be papered over: if every
widening still fills no line, it throws `invalidResponse` rather than hand back an empty
pool that the session screen would render as an unending wait. It never fails for a reason
outside itself — no service, no quota, no connection — which is the property that actually
matters, but "never errors" was too strong.

A frame only applies when `minSyllables <= target <= maxSyllables`, so the bank must cover
the whole range a phrase can ask for. When it doesn't, a last-resort sweep widens the target
until something fills — which does not error, but *silently answers a different question*,
handing back a three-syllable line for a one-syllable phrase. That was the live behaviour for
1–2 syllable phrases until the bank gained short frames; coverage at the short end matters
precisely because the failure is quiet.

**Moby's POS tags are dirty and most of the guard code exists because of it**: it tags "a"
as a noun, "your" as an adjective, "l" as a noun, and those are the highest-frequency words
in English, so they head every Zipf-sorted bucket. Every guard (`contentSlotStopWords`,
articles barred from non-article slots, inflected forms barred from bare-verb slots, single
letters and profanity barred, and `isAcceptable`'s adjacent-pair grammar) is load-bearing
and has a regression test. These membership tests run in the innermost beam loop, so they
are `Set<Int>` of lexicon row numbers resolved once — never `Set<String>`.

**Word sparks:** a word-level assembler cannot guarantee *meaning*, so on the offline tier
the session screen leads with **sparks** — evocative words that fit the phrase's emotion and
beat — and demotes the generated line beneath them. `LexiconSparkProvider` fills two tiers in
order: curated vocabulary from the book's Trigger Word Library, *shuffled* with the phrase
seed, then statistical picks. Ranking the curated tier instead of shuffling it froze the
panel to the same six words every phrase.

**Cost:** zero. Generation is on-device on every tier; there is no per-request cost and no
usage cap beyond the free tier's daily premium budget, which exists to price the product,
not to pay for inference.

**Voice Memo Resurrection:** `.fileImporter` (m4a/wav/mp3) → same DSP chain at ~15–20× real
time with progress → phrases → DTW contour clustering (32-point resampled) → sections
("A/B/A′") + hook = most-repeated high-energy cluster → per-phrase suggestion cards; batch
"lyricize whole memo" runs serially to keep the memory cache-prefix warm.

## 10. Concurrency model

Five isolation domains, Swift 6 data-race safety from day one:
1. **Audio tap thread** — memcpy to SPSC ring only (the one `@unchecked Sendable`).
2. **AnalysisWorker dedicated Thread** — all DSP mutable state confined here; yields
   `Sendable` events via `AsyncStream` continuations (`.bufferingNewest`; UI streams drop, the
   phrase stream doesn't).
3. **`@MainActor`** — ViewModels + SwiftUI; consumers in `.task {}`-scoped `for await` loops;
   explicit `cancelTasks()` on disappear.
4. **`@ModelActor SongStore`** — the only code touching `ModelContext`.
5. **Cooperative pool** — both lyric providers as stateless `Sendable` structs;
   cancellation checked before decode so a superseded phrase never overwrites newer UI state.

No `DispatchQueue` outside AVAudioSession notification handling; no locks or semaphores
anywhere.

## 11. Testing strategy

Swift Testing, **no mic, no network**. The Domain and LyricEngine suites are pure Swift and
run on a Linux container in CI; MelodyKit and the app target need macOS + Xcode and are run
locally (`docs/BUILDING.md`). Targets: Domain ≥ 95% coverage, services ≥ 80%.

1. **Domain (pure — the goldmine):** table-driven tests for StressMapDeriver (note-event
   literals → expected `SwSwwSw`), SyllableCounter (~300-word golden table incl. traps: fire,
   every, poetry), CandidateRanker invariants (a budget-violating candidate can never outrank
   a fitting one; misstressed candidates sink), EmotionFeatureScorer (labeled vectors →
   top-1), ContinuityScorer goldens.
2. **DSP with fixture audio:** synthesized WAVs (exact ground truth: sine/sawtooth melodies,
   click tracks, vibrato tones, noise negatives) + 6–8 real hummed/guitar/piano recordings
   with hand-verified golden `PhraseSpec` JSONs. Tolerances: pitch ±20 cents, onset F1 ≥ 0.9
   (±50 ms), tempo ±3 BPM, boundaries ±120 ms, syllable budget exact clean / ±1 noisy. Plus:
   bit-identical determinism (same file twice), DEBUG malloc-hook zero-allocation assertion,
   faster-than-realtime CI throughput test. **Release gate:** syllable exact-match ≥ 80%,
   within-±1 ≥ 97% on the melisma-heavy corpus.
3. **AI layer, zero network:** zero network is enforced, not asserted —
   `tools/check_no_network.sh` fails on a networking import, a networking API, or a package
   dependency fetched from a URL, and CI runs it on every pull request. Foundation Models
   availability is hardware-dependent, so the tier is exercised through a fake at the
   `LyricProviding` seam (which tier leads the layout, that starting a session warms the
   model) and the deterministic offline provider is tested exhaustively: exact-match via
   seeded RNG, memory caps in rendered prompts, and the template harness (every template
   must satisfy its own stress signature). No HTTP fixtures, no retry/backoff policy, no
   golden request shapes — earlier revisions listed all of those for the cloud tier that was
   never built.
4. **ViewModels with `AppServices.fakes()`:** state-machine walks, supersession/cancellation
   via spies, accept-persists/regenerate-records-rejection, offline badge without error state,
   weak-reference leak test.
5. **Persistence:** in-memory `ModelContainer` round-trips, cascade deletes, blob version
   tolerance, concurrent-append serialization.

Not unit-tested (deliberately): AVAudioEngine wiring (debug diagnostics screen + manual QA),
SwiftUI bodies (previews + VM tests), and Foundation Models generation itself (its
availability is hardware-dependent, so suites exercise the seam with fakes and validate the
deterministic offline tier exhaustively).

## 12. Permissions & error states

Mic only — no speech recognition, no `NSSpeechRecognitionUsageDescription`. Pre-permission
explainer ("Song Finisher listens to your melody on this device") before the system prompt;
denied → dead-end screen with Settings deep link; re-checked on `scenePhase == .active`.
Interruptions (calls/Siri) pause and auto-resume; the current phrase force-closes if ≥ 700 ms.

Typed error taxonomy the UI switches over: `micPermissionDenied`, `audioEngineFailed`,
`noPitchDetected` ("try humming closer to the mic"), `tooNoisy` (proactive banner from
noise-floor tracking, *before* a wasted take), `aiUnavailable` (silent offline degrade + badge
— never a modal), `persistenceFailed`. Polyphony heuristic → "I work best with one note at a
time" hint.

## 14. Top risks & mitigations

1. **Wrong syllable count/stress map breaks the core promise.** Mitigated by melisma merging,
   confidence-widened tolerance ("8–10 syllables" instead of false precision), the live
   syllable meter (users see and re-hum miscounts), ±1 auto-repair, +1/−1 chips, and the
   annotated-corpus release-gate metric.
2. **Generation latency kills flow.** No longer a cloud risk — there is no request, no
   quota and no outage — but Foundation Models lazy-loads, and that load is seconds long the
   first time. Mitigated by `prewarm()` fired when listening starts (so the load overlaps the
   writer settling in front of the mic), the deterministic offline tier as an instant floor,
   and latest-phrase-wins cancellation so a slow phrase never blocks the next one.
3. **SwiftData/strict-concurrency landmines late in the project.** Mitigated structurally:
   SwiftData quarantined behind one seam (worst-case swap is days, not a rewrite),
   `VersionedSchema` from day one, memory-as-blob removes the churniest shape from migrations,
   Swift 6 mode on from the first commit.
